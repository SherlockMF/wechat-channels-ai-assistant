# 脚本工作台功能设计

## 目标

在「发布前审片」之前新增「脚本工作台」：按视频制作形态与业务主题，生成可拍的口播稿或可剪的跟拍/成片大纲；支持复制到备忘录/剪映使用，并在工作台内简单存档。第一版不强制与审片硬关联。

## 背景与内容盘点（本地片库）

本地约 89 条成片、81 条带播放数据。抽样看画面后，制作形态与业务主题需分开建模：

- 口播种草约占一半：痛点字幕 + 产品/效果素材 + 口播/清单字幕，时长多为 20–40 秒。
- 人设 Vlog、项目完工成片、水电/工地、品牌一站式服务、展厅讲解均有稳定画面模式。
- 业务上高频为全屋净水、全屋智能（含灯光/窗帘/影院/安防等子品）、水电工程、综合服务；智能安防片量不小，但产品归类上归入全屋智能子品。
- 用户计划加强服务向内容，并新增「服务过程」跟拍（谈方案、验标准、看进度）。

## 用户流程

导航顺序：

`脚本工作台 → 发布前审片 → 数据匹配 → 数据分析`

页面：

1. `/scripts`：脚本列表；按形态/主题筛选；搜索；复制；编辑；删除。
2. `/scripts/new`：选制作形态 → 按规则选业务主题/子品 → 填该形态输入 → 生成。
3. `/scripts/[id]`：查看/改稿/分段或全文复制；可再生成；弱入口「去审片」可后置，第一版不强制。

## 类型模型

### 制作形态（决定管线）

| 制作形态 | 管线 | 业务主题 |
|----------|------|----------|
| 口播种草 | 口播线 | 必选 |
| 展厅场景口播 | 口播线 | 必选 |
| 服务介绍 | 口播线 | 必选（多为综合服务） |
| 项目完工成片 | 跟拍/成片线 | 必选 |
| 水电/工地展示 | 跟拍/成片线 | 默认「水电工程」，可改 |
| 服务过程 | 跟拍/成片线 | 必选 |
| Vlog | 跟拍/成片线（轻量） | **可选**；不选也可进入下一步 |

### 业务主题（一级）

- 全屋智能
- 全屋净水
- 水电工程
- 综合服务（一站式、一小时等）

### 全屋智能子品（可多选）

灯光开关 · 窗帘 · 影院影音 · 语音中控 · 中控面板 · 智能安防 · 综合场景

净水可选角度标签（非一级）：软水效果 / 中央净水 / 厨下 RO / 母婴即热 / 生活场景（泡茶护肤等）。

### 服务过程子类型

可多选：跟业主谈方案 · 现场验是否按标准装 · 看施工进度。

## 管线设计

采用类型驱动双模板（口播线 / 跟拍成片线），避免单一万能长表单。

### 口播线输入

- 必填：一句话选题或想法。
- 可选：强调卖点、目标时长（口播默认 20–40 秒；展厅可 45–90 秒）、语气（口语 / 偏干货）。
- 主题 +（若全屋智能）子品。

### 口播线产出

1. 标题备选 2–3 个 + 建议标签。
2. 完整可念口播稿：痛点钩子 → 方案/产品 → 1–2 个场景卖点 → 收束/CTA。
3. 穿插素材提示（按段落）。
4. 字幕要点（顶栏大字 / 底栏字幕短句）。
5. 可选第二版钩子，方便拍 2–3 条选一条。

展厅场景口播额外：站位与演示动作提示。  
服务介绍额外：服务步骤或「省事/省钱/省心」卖点，少堆单品参数。

### 跟拍/成片线输入

- **项目完工**：项目类型、已拍或计划画面要点、本周突出点（至少填一类）；可选内部备注（房型/小区，默认不对外）。
- **水电/工地**：现场亮点、要强调的标准点。
- **服务过程**：过程子类型、客户场景一句、今天必拍节点。
- **Vlog**：今天大概有什么（自由文本）；主题选了只当标签。

### 跟拍/成片线产出

- 本片一句话定位（Vlog 可为当日主题句）。
- 拍摄或剪辑顺序（时间线 / 素材排列）。
- 每段：拍什么、可说什么（口头提词，非长口播）、字幕短句。
- 可删可补或敏感提醒（服务过程：门牌、合同、客户脸等打码/避免入镜）。
- Vlog：不硬套产品结构；若带主题，最多一处自然露出提示。

### 操作

全文/分段复制；改稿保存；再生成（默认另存为新记录，保留旧条可查）；状态：草稿 / 可用。

## 数据模型

LOCAL 模式写入 `.data/local-state.json`，与审片一致。脚本工作台第一版不强制存储视频文件。

建议实体：`ScriptDraft`（名称实现时可微调）。

字段要点：

- `id`, `ownerId`, `createdAt`, `updatedAt`
- `format`：制作形态枚举
- `topic`：业务主题，可空（Vlog）
- `subTopics`：全屋智能子品等，可空数组
- `processKinds`：服务过程子类型，可空
- `title` / `ideaSummary`
- `input`：用户原始输入结构化对象
- `output`：结构化产出 + `plainText`（便于一键复制）
- `status`：`draft` | `ready`
- `referenceVideoIds`：可选，生成时参考过的历史片
- `draftReviewId`：第一版不写；预留

建议结果结构（概念）：

- 口播：`titles[]`, `tags[]`, `script`, `brollCues[]`, `subtitleBeats[]`, `altHooks[]`
- 跟拍/成片：`positioning`, `timeline[]`（order, shoot, say, subtitle）, `gapsOrWarnings[]`

## 生成依据

1. 用户当次输入（主依据）。
2. 形态 × 主题提示模板（固定结构，减少跑题）。
3. 可选：从本地导入片库按主题/标题取 2–3 条相似历史（播放/完播作参考，不要求仿写）。
4. Vlog 且无主题：不拉产品向相似片，只用轻量大纲模板。

Provider 对齐审片：`mock` / DashScope（或现有 LLM 配置）；无 Key 时 mock 可跑通。

## 与现有模块关系

```text
历史 imports/matching 数据 ──可选参考──► 脚本工作台 ──人工拍摄剪辑──► 发布前审片 ──发布──► analysis
```

第一版：

- 不自动创建审片任务。
- 不上传口播成片到工作台。
- 不做剪映工程导出。
- 审片详情可后续加「关联脚本」弱入口，非本版范围。

## 约束与非目标

- 仅 LOCAL 仓库实现即可与审片对齐；Cloud/Postgres 可同审片一样暂未支持或后续补。
- 生成文案需人工终审；不保证平台推荐结果。
- 服务过程强调信任与真实，避免写成硬广口播。
- 不把「暖通空调」做成一级主题（片库几乎不构成独立线）。
- 不把智能安防做成一级主题（归全屋智能子品）。

## 验收标准

1. 导航最前出现「脚本工作台」，顺序在审片之前。
2. 七种制作形态可选；Vlog 不选主题仍可生成并保存。
3. 口播线产出含可复制口播稿与素材提示；跟拍线产出含顺序大纲。
4. 服务过程为完整形态（谈方案 / 验标准 / 看进度），非占位。
5. 列表可筛选、复制、编辑、删除；再生成保留历史记录。
6. mock 与配置 LLM 下均可完成「新建 → 生成 → 复制」闭环。
